## 每篇檔案的固定結構

為了讓吸收有節奏，所有主題都照同一套骨架寫：

1. **30 秒總結** — 五句話帶走全部
2. **學習地圖** — 核心觀念之間的因果鏈
3. **核心觀念 N 節** — 每節：一句話結論 → 為什麼 → **法條原文（可展開）**
4. **對照表／四宮格** — 把文字壓成可掃描的表
5. **優缺點分欄** — 正反並列，不藏缺點
6. **地雷清單** — 實務上會出事的地方
7. **記憶口訣** — 四句話對應四條法條
8. **自我測驗** — 點擊翻答案，先想再看
9. **法條原文總表** — 全部引用條文＋官方連結

```bash
cd C:\Claude\projects\study
cp -r _template 002-your-topic-slug
# 編輯 002-your-topic-slug/index.html 與 README.md
# 在本檔與 index.html 各加一列索引
git add . && git commit -m "study 002: your topic" && git push
```

命名規則：`0NN-英文短名`（純 ASCII，避免中文資料夾名在 GitHub Pages 上的編碼問題）。

## 原則

- **法條一律附原文**，不只給結論。條文會修，結論會過期，原文＋連結才查得回去。
- **不藏缺點**。優缺點分欄並列，任何「這個很棒」旁邊必須有「但是」。
- **可驗證優先於好看**。每個數字、稅率、門檻都要指得出來源。
- **不是法律意見**。個案執行前請由會計師／地政士／律師出具書面意見。
